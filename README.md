## 这是什么

JICEDA-MCP 是一次面向立创 EDA 的本地 MCP 工程实验。目标不是重写 EDA，而是在 Codex、OpenCode 等宿主与立创 EDA 之间提供一层可机械核验的能力：

- 读取原理图 / PCB 的统一设计快照；
- 做只读连通检查、审查报告和设计意图差分；
- 在明确绑定目标、冻结计划和回读核验的前提下执行有限修改；
- 区分“接口返回成功”“对象几何正确”“网络正确”“保存后可回读”“重开后仍一致”等不同证据等级；
- 在超时、身份变化和未知状态下保留现场并阻止盲目重放。

最初设想的验证范围是 **10–30 个器件、低速低压、单页原理图、双层 PCB**。KiCad 和独立 Agent 属于后续方向，目前没有本项目 KiCad 实机适配验收。

## 这不是什么

本项目目前**不是**：

- 稳定的自动原理图 / PCB 设计工具；
- 可一键安装的发行版；
- 通用事务、自动回滚或自动取消系统；
- 已通过电气功能、制造质量或硬件验证的 EDA 产品；
- 立创 EDA 或任何宿主厂商的官方项目。

MCP 只是调用协议，不能替编辑器接口自动补上事务、保连移动、取消和完成状态确认。

## 为什么暂停

最后一轮没有继续新增演示或编辑能力，而是收敛工程绑定、就绪判断和超时状态。12 器件案例的绑定和原理图两次精确读取通过，但切换到空 PCB 图页时约 30 秒后收到：

- `DISPATCH_FAILED`
- `connector did not respond`
- `context deadline exceeded`

在我这边观察到上游自动探针等待 5 分钟仍无答复，底层完成状态无法确认。新增的跨通道 / 跨进程持久隔离阻止了后续渲染端派发，另一个 15 器件案例的新进程也无法绕过这条未知状态。在这次测试中，我观察到隔离机制按预期阻止了后续操作，但这**不足以推断第二个电路验收通过，更不等于自动设计完成**。

因此我的个人决定是：在必要调用的完成状态、取消或隔离机制没有得到可靠验证前，暂不继续用重启、额外窗口或放宽核验来追赶完成度。这是个人项目的暂停，不是对平台能力的最终判断。

## 当前能力与证据等级

| 能力 | 状态 | 说明 |
|---|---|---|
| 双宿主只读调用 | 局部通过 | 在 P0 合成电路上，Codex / OpenCode 实际模型各调用三个只读工具，结构、内容 / 拓扑签名和 findings 一致 |
| 统一设计快照 | 局部通过 | 器件、引脚、网络及可读取几何；未采集数据标为缺测，不用空列表冒充“没有对象” |
| 只读连通与审查 | 局部通过 | 悬空、异常同网、设计意图差分等；报告包含定位、依据、严重程度和覆盖局限 |
| 工程绑定与身份恢复 | 局部通过 | 显式绑定、文档清单分类、重复 / 冲突身份拒绝、超时共享隔离 |
| 计划 / 执行 / 回读核验 | 局部通过 | 小案例完成有限编辑、保存核验和重复提交防护 |
| 有限原理图编辑 | 局部通过 | 显式引脚连接、分支、NC、部分标签和几何专项；不是通用自动连线 |
| PCB 无铜平移 | 局部通过 | 特定计划、逐件保存重载；不支持带铜保连移动 |
| 有限 R/C 计算 | 局部通过 | 标称 R/C 网络直流、正弦分析及有条件电源 / 电阻检查；不覆盖完整瞬态、容差和全部器件模型 |
| 完整端到端设计 | **未通过** | 两结构各连续三轮的实机门槛完成 **0/6** |

> 接口返回成功只是第一层。几何、网络、非目标对象、保存回读、重开一致必须分别签核。截图可以辅助检查可读性，不能替代网表和持久化证据。

## 架构概览

```text
Codex / OpenCode
        ↓
本地 stdio MCP：明确参数的工具
        ↓
统一快照 / 设计意图 / 模块与约束 / 确定性规则
        ↓
冻结计划 / 前置条件 / 执行回执
        ↓
目标绑定 / 共享锁 / 超时持久隔离
        ↓
立创适配层：原生 V4 CLI + 社区 CLI / connector
        ↓
立创 EDA 桌面编辑器
        ↓
独立回读 / 保存重载 / 重开核验
```
